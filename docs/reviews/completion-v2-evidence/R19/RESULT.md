## Implemented contract

Readiness checks run actual bounded SELECT1 and configured Redis service set/get/read-back/delete rather than local cache statistics. The Redis adapter uses a separate short-lived connection with offline queue disabled, bounded connect/command timeouts and no retry loop; it disconnects on failure, success and abort. Health probe keys have random identities and a five-second TTL. No real Redis was contacted in this slice; injected adapter tests establish command wiring and cleanup only.

The core runs probes concurrently under a1500ms deadline, leaving500ms for HTTP handling within the two-second specification. It aborts timed-out adapters and shares outstanding work; an adapter that never settles retains one unhealthy result instead of creating a new queued operation per request. A settled failed probe can retry and recover. The outer deadline does not cancel a pg pool query; query_timeout1000ms and the existing pool acquisition bound limit that work, and single-flight prevents multiplying a stuck query. Actual DB outage/pool/TLS evidence remains pending.

Production or explicitly configured Redis absence/failure is unhealthy. Unconfigured optional development Redis is reported not_configured rather than falsely healthy. Readiness/startup return503 for required failure or shutdown, including shutdown that starts while probes are pending. Public responses contain only aggregate/dependency status; driver messages, hostnames, paths, finance payloads, latency and package/uptime details are omitted. Liveness is process-only. Hosted revision/operator/job-staleness reporting remains a later protected operations interface, not a public diagnostic dump.

Logger now serializes sanitized context rather than selecting a few keys and losing outcomes. Deep redaction copies structured objects/arrays, masks sensitive credential/identity/financial/body/query keys, bounds traversal/strings/arrays, preserves useful run/job/provider/outcome/count/token metrics, protects envelope fields, handles cycles/bigint/accessors, and serializes Error class/validated code without raw message, stack, SQL or cause payload. Existing masked user/household ID semantics are preserved. Messages remain caller event labels; auditing every existing freeform/interpolated message and all domain-specific payload keys is not claimed by this foundation. Callers must put diagnostics in structured context.
