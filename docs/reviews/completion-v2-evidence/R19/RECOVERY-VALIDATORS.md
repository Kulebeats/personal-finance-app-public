# R19.3 pure recovery contract and native command planning

This is the first implementation slice of the accepted RECOVERY-PLAN.md (a609600 + e12cf08). It supports only a bounded local synthetic contract. It has no launcher, file reader/writer, database connection, archive parser, object transfer or application imports. No database, artifact directory, credential file or backup was created. No pg_dump/pg_restore or provider request ran. Full recovery, RPO/RTO and production readiness remain OPEN.

## Interfaces and trust boundary

New scripts/recovery/contracts.mjs exports readProducerIntent, readPublishedBundle and readRestoreAuthorization. Each consumes an exact canonical JSON string; producer and restore also require separate caller-supplied expected identities/digests. Unknown fields refuse. There are no candidate, tool, schema, target, credentials or approval defaults. Module-private record identity and deep freezing prevent a cloned, forged, changed or wrong-stage object from reaching the next stage/planner.

The producer binds its revision, candidate/rollback SHAs, schema/journal hashes, exact source/restore target manifests and tool paths/versions/hashes. Outputs are names only: archive digests do not exist at intent approval. Source and restore have distinct DB names/run IDs, use numeric 127.0.0.1 at the exact caller-pinned non-5432 port, and satisfy the existing disposable target parser. Reserved names, URL database strings, extra target fields and same-target reuse refuse. The imported target module has no import-time DB/filesystem dispatch; only its pure validateManifest/markerFor functions are used.

Published bundles bind the producer, source, candidate, schema/journal and cut/publication times, archive and object-sidecar lengths/hashes, and bounded object keys/ownership/purpose/media type/size/hash/version/blob references. A bundle structure is not provenance: the subsequent immutable restore authorization must independently pin the producer, bundle, archive and sidecar digests. A replaceable archive accompanied by its own hash does not supply these trusted pins. This library cannot establish who supplied a pin or that approvalRef represents owner permission; the later parent-reviewed dispatch must supply that independent authority.

Restore additionally binds the separate destination and expected template0 baseline, quarantine=true, an independently pinned security authority and an exact recovery watermark. The supported first profile is only synthetic-no-post-cut-markers. Missing/stale authority, an unsupported replay mode, a recovery watermark before publication or over 24 hours after the joint cut refuses. This checks declared timestamp arithmetic, not actual incident time, completeness, durable erasure authority or a measured RPO. Production/app manifest schemas, lifecycle coverage, bucket identity, independently read object-sidecar contents, capture observation records and actual post-cut replay are deliberately not fabricated by this transport contract.

Canonical version 1 is sorted object keys, compact JSON, integers only, no duplicate keys/alternate whitespace/escapes, bounded depth/nodes/strings and <=1MiB input. Caller pins use the same bounded canonical copy; getters, symbols, non-plain objects, sparse arrays and hidden array properties refuse rather than silently disappearing. Refusals use a static message without echoing supplied payloads. The fixture module contains synthetic placeholder identities/hashes only and is not an approved manifest or evidence that any named tool/path/target exists.

## Pure native plans

scripts/recovery/plan.mjs accepts only validated stage records. Capture plans a new database.dump.partial custom archive; restore requires the later authorization and plans the completed archive into the distinct destination. Argument arrays contain explicit host/port/user/dbname and no-password. Restore includes no-owner/no-privileges/no-comments/exit-on-error/single-transaction; create, clean, arbitrary flags and connection URLs have no input field. The command has shell=false and the explicit finite deadline from the intent.

The first native planner targets the selected Windows host. Credential passfile, temporary directory and SystemRoot must be explicit caller paths. The passfile and temp directory must be disjoint strict descendants of the separately pinned credential root, itself disjoint from the artifact root. Environment output is limited to PGPASSFILE, PGSSLMODE=disable (only this guarded local synthetic profile), PGCONNECT_TIMEOUT, PGAPPNAME, SystemRoot, TEMP and TMP. It never reads/spreads process.env or introduces a password, PATH, PGOPTIONS/service/URL routing defaults. The future launcher must replace its child environment with the planned map rather than merge it with ambient variables.

Path handling is lexical only: absolute normalized paths, strict descendant/disjoint checks, no traversal, UNC/device/drive-relative paths, ADS, encoded separators, short-name alias syntax, reserved device names or trailing dot/space ambiguity. Actual symlinks, junctions, hardlinks, filesystem case behavior, ownership/permissions, create-only output, binary dependencies and TOCTOU remain unverified. Every validated record and plan explicitly returns false certifications for filesystemIdentity, liveDatabaseIdentity, actualBinaryHash and executionAuthorized. Expected markers/hashes are expectations for a future preflight, never a record that preflight succeeded.

Before any launcher: parent/reviewer must approve exact source/destination/artifact identities and provenance; the R20 creation-only helper must establish explicit TEMPLATE template0 and a pristine all-object baseline; protected live checks must verify each own marker/endpoint and source schema/journal; resolved filesystem paths/reparse points, private passfile and immutable binary hashes/versions must be checked; bundle bytes/TOC/sidecar/object hashes and security authority must be independently read. Capture needs owned lock/quiescence and atomic complete publication. Restore needs quarantine, a current replay authority, total RTO supervision and post-restore marker/data/object readback. Those capabilities are absent here and are not permission to execute.
