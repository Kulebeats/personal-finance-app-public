## Exact selected files and checks

scripts/recovery/filesystem.mjs accepts only module-branded validated producer or restore records. Producer selects its two exact pinned tool paths/hashes. Restore additionally selects the pinned archive, object sidecar, canonical bundle manifest and each content-addressed object blob. Archive/sidecar/blob sizes come from the validated bundle; bundle bytes/length derive from its canonical representation and independently authorized digest. Explicit toolSizes are separate caller-provided expected-size pins (positive, bounded, no automatic stat-derived defaults). No credentials, directory scan, arbitrary extra file list or custom command flag is accepted. Identical content-addressed blob references share one read; conflicting size/hash or case aliases refuse.

Lexical controls reuse the accepted absolute/normalized/descendant rules, rejecting traversal, UNC/device paths, ADS, encoded separators and short-name/device aliases. The Windows-only observer walks every ancestor from drive root through the exact leaf: lstat must identify directories/regular files without links, the native realpath must agree, and file link count must be exactly one. Nonregular/missing files or hardlink aliases refuse. Descriptor fstat identity must bind the pre-open path identity. Reads are read-only, fixed 64KiB chunks bounded by the expected length; SHA-256 and exact size must match. Files' device/inode/mode/link count/size/birth/change/write timestamps are rechecked, along with ancestor device/inode/mode/birth identity and Windows attributes. Directory write timestamps are intentionally not stability assertions: unrelated sibling operations can change them without changing the selected ancestor identity.

All descriptors remain open through the final path/metadata/descriptor checks and close before the promise returns, including refusal paths. The result is immutable. It records only matching expected hashes and observed identities, not file contents. A hash match does not authenticate provenance: caller pins still require independent parent-reviewed authority. This slice does not parse SQL/TOC or the object sidecar, establish a pristine template0 DB, verify live markers/journal, execute a tool to confirm its version, or reconstruct any object store.

## Authorized read-only Windows metadata bridge

Node's link abstraction does not certify absence of every Windows reparse tag; upstream [libuv Windows filesystem handling](https://github.com/libuv/libuv/blob/v1.x/src/win/fs.c) distinguishes recognized links from other reparse points. This is why the slice does not equate isSymbolicLink=false with a fully clean Windows path. scripts/recovery/windows-metadata.mjs uses only the selected SystemRoot\\System32\\WindowsPowerShell\\v1.0\\powershell.exe, matching the trusted process SystemRoot, with a regular/non-link/native-path bootstrap check. SystemRoot is explicit and a different caller shell root refuses. The installed OS bridge/bootstrap remains a trusted dependency; this is not an independent attestation of Windows, its modules, ACLs or all DLL dependencies.

The fixed child argument array is -NoLogo/-NoProfile/-NonInteractive/-Command plus a static script; shell=false, windowsHide=true, a five-second deadline and bounded output apply. The script receives only bounded validated JSON paths on stdin, never interpolated code. Its only filesystem operation is Get-Item -LiteralPath -Force, collecting attributes, length and creation/write times. [LiteralPath treats supplied values literally](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-item?view=powershell-5.1). The script and Node output validator reject the [ReparsePoint attribute bit 0x400](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants) on every selected ancestor/file, regardless of reparse tag. It performs no explicit file writes, credential reads or recovery commands. No profiles, arbitrary executable/arguments, stdin shell code or ambient PATH/PowerShell/PG defaults enter the child environment. Child/process/stdin/parse/shape/attribute failures refuse without echoing supplied paths/payloads.

Windows metadata is collected before and after descriptor hashing; file lengths and creation/write ticks bind back to Node metadata, and attribute/identity observations must remain stable. A metadata bridge failure is not downgraded to a clean Node-only result. Actual owned-junction tests exercise both the Node ancestor check and the independent PowerShell attribute refusal. A literal path containing dollar/subexpression/wildcard-looking text is processed as a filename, with the actual fixed child executable/arguments/environment asserted in the test.

## Explicit remaining TOCTOU and authorization gates

The result certifies only descriptorReadback and observed windowsReparseAttributes for this operation. laterNativeReopenSafe, provenanceAuthenticated, ownershipOrAcl, liveDatabaseIdentity and executionAuthorized stay false. Metadata/path checks are observations through separate calls, not atomic locks preventing an adversary from changing paths between observations. A native pg process later reopens a pathname after these descriptors have closed; this module does not make that reopening safe or grant execution permission. A reviewed launcher still needs trusted immutable tool/artifact/credential custody, independent provenance, immediately adjacent identity checks/owned locks and the accepted live DB/TOC/security/quarantine gates. No filesystem ownership/ACL, global no-race, actual binary version, RPO/RTO or recovery acceptance follows from matching file attributes/hashes.
