The application now uses `GuardedSessionStore`. Authenticated/pending-MFA writes and touches lock the user row, read generation/erasure/tombstone state, then persist on the same PostgreSQL transaction connection. Revocation uses the same user-first lock order. Store reads independently reject stale or erased identity. A refused late save is a successful no-op, preserving callback completion without persisting the old payload; it never adopts the current generation.

Selected-device and logout revocation persist SHA-256 SID tombstones, remove the actual session and tracking rows atomically, and leave unrelated sessions/user generation intact. Login finalization carries the verified user's generation/password snapshot and checks it again before creating a session. Tracking creation locks the user and rechecks the same credential snapshot; it fails closed instead of swallowing tracking failure. Pending MFA stores its original generation; reset cannot upgrade an old challenge to a current login. Step-up records both user and session identity; copying its timestamp to another session is insufficient. Erasure's identity cleanup was extracted from the oversized service to keep the existing LOC ratchet green.
