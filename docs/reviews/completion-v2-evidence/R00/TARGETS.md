## Manifest and bootstrap contract

Committed `server/testing/fixtures/target.example.json` is an example of intent, not permission to use any existing endpoint. Supply `TEST_DATABASE_URL`, `TEST_RUN_ID`, `TEST_TARGET_MANIFEST`; browser runs also require `server.origin` in the manifest. Bootstrap additionally requires `TEST_DATABASE_ADMIN_URL` whose database is exactly `postgres` on the same loopback host and explicit port. No URL query or fragment is accepted. Database paths must be plain, unencoded names; manifest fields match exactly. Allowed names are `pfa_completion_*_<runId>_test` or `pfa_ci_*_<runId>_test`, at most 63 characters; run id is 8-32 lowercase alphanumeric characters beginning with a letter. `finance_app`, `finance_app_test`, arbitrary `*_test`, unknown hosts, missing marker and stale run ids refuse.

`node scripts/create-test-target.mjs <manifest.json>` writes a credentials-free manifest from explicit test variables and refuses overwrite. It neither connects nor loads `.env`. Existing unmarked databases are never adopted. Bootstrap writes the shared-catalog database comment `pfa-synthetic-test:v1:<runId>:<database>` only when it creates a new synthetic DB; then verifies target identity before versioned migrations. `host(inet_server_addr())` deliberately strips the `/32` or `/128` mask of PostgreSQL's inet text rendering. An early maintenance identity attempt refused safely before CREATE until this was corrected.

Every worker validates pg's resolved connection parameters before connection and reads the persisted marker before returning a client or Pool connection. `Client.query` refuses until verification, including a query queued immediately after `connect()` or from a connect listener. Temporary error listeners propagate marker-phase socket failures once and keep Pool from receiving an unverified client. No connection-string query overrides or ambient PG host/database/options can redirect a permitted connection.

Outbound credentials are assigned empty strings before application imports; Redis is disabled. Later dotenv/config uses a deliberately empty file and cannot restore missing keys. The network guard independently denies TLS, remote sockets, arbitrary localhost endpoints and unix sockets. The verified synthetic DB endpoint and listeners actually created by the current test process are the only allowed destinations; this preserves Supertest ephemeral HTTP listeners. Paid/provider, real mail and push dispatch cannot be re-enabled by `.env`.
