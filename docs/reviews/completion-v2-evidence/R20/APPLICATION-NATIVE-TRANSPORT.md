## Contract and environment

`diagnoseApplicationNativeResolution(requestText, expectedRequestSha256)` takes
closed canonical JSON and independent expected bytes hash. Each edge preserves
its graph parent, actual parent URL/pin, original kind, mode, specifier and count.
Unknown invocation controls, duplicate tuples, pin drift and parent aliases refuse.
The runtime is the fixed pinned Node24.22.0 Windows ARM64 executable. The fixed
neighbor child receives exactly `--experimental-import-meta-resolve` and invokes
native `import.meta.resolve` with the actual parent URL. Both modules import only
builtins; no caller harness or resolver callback is accepted.

Runtime, both harness files and physical parents receive descriptor-bound pin
checks before/after; this is sampled identity checking, not continuous custody
or proof that already-loaded bytes remain identical. The future observer must
establish the complete approved lookup footprint before invoking this transport.
The transport does not measure selected file bytes or package scopes.

Native throws preserve bounded error codes. Returned missing paths and directories
have distinct diagnostics after actual lstat. Every JavaScript `.js` target remains
unestablished-format; no source detection or package-type guess occurs here.
Require/nonliteral/unsupported edges remain explicit blockers. All result
acceptance, root-completeness, stage, custody, module-identity and execution flags
are false; outputs have no private acceptance lineage.

The initial actual run passed4/8 and refused4/8 because Windows child creation
inserted environment keys. Diagnosis used names/stack only, not credential values.
The correction explicitly supplies16 fixed keys/values, validates the entire
resulting environment and supplies empty NODE_OPTIONS, NODE_PATH and
NODE_V8_COVERAGE. No ambient identity values are copied. Exact values and versioned
Node/libuv source references are retained in HANDOFF.md and the pinned source.
