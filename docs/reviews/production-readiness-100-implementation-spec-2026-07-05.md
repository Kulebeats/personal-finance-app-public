## Operating rules (runtime-neutral)

1. **Isolated worktree/branch per packet** off latest `origin/main`; confirm the branch (`git branch --show-current`) before every commit — parallel sessions share the main checkout. Install `node_modules` fresh in a worktree (npm ci); never junction it from the main checkout (corrupts the incremental tsc cache).
2. **One PR per packet**, conventional-commit titled, targeting main. Merge only when the packet's tier DoD is met, CI is green on the branch head, and the ledger row is updated with evidence. **No destructive Git actions without explicit user approval: no branch deletion, no force-push, no history rewrite.** Merged branches are left in place unless the user says otherwise.
3. **Small diffs, one concern per PR.** Dependency groups are separate PRs precisely so failures isolate and roll back cleanly.
4. **Checkpoints — pause and surface for:** Render provisioning and dashboard env changes (W9, interactive-only); TLS enforcement flip (W9, after connectivity proof); anything data-destructive outside a test database; any destructive Git action. (The W4 product decision is already resolved — Option (a), record-only — no checkpoint remains for it.)
5. **Money and structure invariants** (Tier A packets): all monetary values through `Money` (`server/core/money.ts`); no `parseFloat`/`Number()`/`Math.round`/`.toFixed()` on amounts; attribute every rate/threshold/convention to a named source (ZRA rule, BoZ convention, product decision, existing test expectation) and flag uncertain ones rather than asserting; a missing FX rate is a surfaced, logged error, never a silent 1.0; V7 envelope via `server/core/http`; error classes from `server/core/errors`; thin controllers; Zod `.safeParse()`; rate-limit tier on every route; LOC limits (<500 server, <300 new client, <100 routes); zero `as any`.
6. **Independent verification before ✅:** after each fix claim, run an independent adversarial review pass (fresh-context reviewer/subagent where the runtime provides one; otherwise re-derive the claim from a clean checkout: re-run the greps, the new tests against the old code — they must fail — and against the new code — they must pass).
