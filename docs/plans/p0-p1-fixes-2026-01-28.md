**Issue:** Last member removal - controller doesn't implement check
**Status:** CLOSED

**Problem:**
The removeMember controller function didn't prevent removing the last member from a household, which could theoretically leave a household with zero members.

**Fix Applied:**
Added member count check in [household.controller.ts:254-260](../../server/modules/household/household.controller.ts)

```typescript
// HOUSEHOLD-EDGE-003: Prevent removing the last member
// Get all household members to check count
const allMembers = await householdRepository.findMembers(household.id);
if (allMembers.length <= 1) {
  throw new ValidationError(
    "Cannot remove the last member of the household"
  );
}
```

**Impact:**
- Prevents edge case where household could become empty
- Ensures data integrity
- Adds validation layer before database operation

### P1: TAGS-RACE-001 ✅

**Issue:** Race condition in addTagToTransaction
**Status:** CLOSED

**Problem:**
The addTagToTransaction function had a classic "check-then-insert" race condition:

```typescript
// ❌ OLD CODE (race condition)
const existing = await db.select()...  // Check if exists
if (existing.length > 0) return existing[0];
const result = await db.insert()...    // Insert if not exists
```

If two concurrent requests both check and find no existing record, both will try to insert, causing a duplicate key error or inconsistent state.

**Fix Applied:**
Used PostgreSQL's atomic `ON CONFLICT DO NOTHING` in [TagRepository.ts:81-103](../../server/repositories/TagRepository.ts)

```typescript
// ✅ NEW CODE (atomic operation)
const result = await db
  .insert(transactionTags)
  .values({ transactionId, tagId })
  .onConflictDoNothing()  // PostgreSQL handles duplicates atomically
  .returning();

// If insert was skipped due to conflict, fetch the existing row
if (result.length === 0) {
  const [existing] = await db.select()...;
  return existing;
}
```

**Impact:**
- Eliminates race condition
- Uses database-level atomic operation
- Handles concurrent tag additions safely
- No duplicate key errors
